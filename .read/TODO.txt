验证码是ddos攻击的良好接口之一，因为无需登录即可从服务器获取高成本响应；
目前的防ddos策略：
- 登录失败 2 次后才出现验证码（同时发起 cloudflare JS 质询）
- 每个 ip 每秒只能生成 1 次验证码
- 验证 10 次失败则拉黑 1 分钟。

并发安全：先查再建这种非原子操作，在并发环境下，有概率导致重复建数据。

后续优化登录校验性能：
1. 把“用户状态 + token_version + role + deleted_at”做短 TTL 缓存
2. 不要每次都查 user_models
3. 把 session 有效性做短 TTL 缓存，不要每次都查 user_session_models
4. 只把“撤销、改密、封禁”这些动作当成缓存失效触发器。如果访问量再上来，再考虑把黑名单和 session 状态合并成更紧凑的 Redis 校验链路。

AI 写作助手
可以放在发文和改文流程里，做标题优化、摘要生成、标签推荐、分类建议、SEO 描述生成、错别字修正、语气润色、长文提纲整理。这个最容易见效，也最符合博客后台场景。

站内知识问答
把已发布文章当知识库，做“基于文章内容回答问题”。比如用户问“这个站里有哪几篇讲 Go 中间件？”、“帮我总结作者写过的 ES 相关文章”。这个比普通 AI 对话更有辨识度，也更能提升搜索体验。

语义搜索 / 混合搜索
你现在明显已经有 ES 关键词搜索了，但还偏传统检索。可以升级成“关键词 + 向量召回 + rerank”，支持自然语言搜文，比如“有没有讲高并发缓存击穿处理的文章”，而不只是搜精确词。

评论与内容审核
文章发布审核、评论垃圾内容识别、辱骂/广告检测、低质量评论拦截、给管理员生成审核理由。这类功能和你现有评论、文章审核流天然匹配，而且能直接降低运营成本。

AI 博客助手
你现有聊天系统可以复用，但建议做成“站内 AI 助手”而不是普通陪聊。比如它能回答站内内容问题、推荐文章、解释某篇文章重点、帮用户生成评论草稿、帮作者回复评论。

个性化推荐
结合浏览历史、收藏、点赞、标签偏好，做“你可能感兴趣的文章”“每周精选摘要”“新文章订阅推荐”。这个适合后面做，因为它需要行为数据和推荐策略一起迭代。

多语言能力
比如自动生成英文摘要、中英双语文章、标题翻译、术语解释。对技术博客挺实用，尤其如果你想做搜索流量扩展。

ViewCount 大概方向：
- 统计逻辑：用户主页每1个独立访客访问+1，同一人当日多次访问仅计1次，游客访问不统计
- 去重方案：Redis HSETNX 记录{访客ID:被访者ID}(具体key细节设置你来补充)，整组key每日0点过期
- 数据库：新增UserViewDailyModel（Model、UserID、ViewerUserID、ViewDate），建立唯一索引
- DB 更新方式：SQL事务完成两个操作(原子插入日访问记录+更新总ViewCount)，无需提前查询
- 执行流程：Redis写入式判重 → 无重复则数据库INSERT+UPDATE → DB 失败时回滚 Redis
“HSETNX 抢占式判重 + DB 事务两条 SQL + DB 唯一索引兜底 + 事务失败后最佳努力 HDEL 回滚 Redis”
